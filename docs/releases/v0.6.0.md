## Changes

- Native SwiftUI Mac recovery app: snapshot selection, encryption key or key-file entry, nested disk/volume browsing, search, and file/folder restoration with checksum confirmation.
- Fixed authentication failures for wholly sparse indirect subtrees in raw encrypted ZFS sends. Cryptographic authentication remains mandatory.
- Windows clients now include the C runtime, fixing launch failures on clean Windows installations without VCRUNTIME140.dll.
- Fixed clipped Windows credential labels and improved Mac restore controls and volume sizes.

## Validation

A real encrypted Slide backup from AustinLand was copied into an offline pool image. Mac and Windows CLI and GUI restores of a file inside its nested ext4 disk matched an independent read-only source hash. The original source pool stayed online and unchanged. The automated suite includes 64 tests and a public synthetic sparse-stream regression fixture; real backup data and keys are not distributed.

GitHub CI tests Linux, native Windows, Apple Silicon macOS, and Intel macOS. The Intel build is tested in CI; the interactive real-Slide Mac GUI workflow was exercised on Apple Silicon.

## Installation and limitations

Mac apps require macOS 13 or later. Extract the appropriate ZIP and move **ZFS Explore.app** to Applications. These builds are **ad-hoc signed, not Developer ID signed or Apple-notarized**. Gatekeeper may require approval in **System Settings → Privacy & Security → Open Anyway** after you verify the checksum and source. Windows executables are **unsigned** and may trigger SmartScreen.

This remains experimental recovery software. Sources are opened read-only. RAIDZ and pools with multiple top-level vdevs are unsupported. Folder restore skips links and special files and does not reproduce filesystem metadata. The Mac app's native encryption workflow does not yet expose the Windows/CLI Datto credentials or incremental-update features.
