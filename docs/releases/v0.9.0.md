Both desktop apps have been redesigned so someone who has never used ZFS can get
a file back: open the backup, pick a date, unlock it, find the file and restore a
copy. The apps now say what each step means in plain words, choose sensible
defaults, and point to the next step. Formats, read-only guarantees and the
recovery engine are unchanged. The complete
[visual and usability audit](https://github.com/amcchord/zfs-send-explore/blob/main/docs/desktop-ux-audit.md)
lists every finding with before-and-after screenshots.

## Both apps

- **Restore points instead of datasets and views.** The newest restore point
  that holds files is selected when a backup opens. Entries read like
  "Sep 21, 2026 · 2:00 PM — linux · s_ykccu1r33he1" and "full copy" or "changes
  only" replaces ZFS vocabulary. Live dataset states and parent datasets are
  labelled as such.
- **Slide and Datto backups point to the computer's files.** A banner explains
  that the protected computer's files are inside its disk image and opens it in
  one click.
- **Partitions are named and one is recommended**: "Partition 3 · Windows files ·
  NTFS · 41.9 GB". EFI, recovery, reserved, swap and BIOS-boot partitions are
  identified so they are easy to skip.
- **Problems are explained**: a plain headline and next step, with the original
  engine text under **Show details**.
- **Consistent name**: both apps are now **ZFS Explore**.

## macOS

- A step bar shows *Backup open → Restore point → Unlock → Find files → Restore*.
- Native sidebar of restore points, a welcome screen with large choices,
  drag-and-drop to open, clickable breadcrumbs across nested disk images, and
  labeled **Open** and **Restore…** toolbar buttons.
- Inline unlock with key-format-specific wording and **Choose Key File…**.
- Restore results lead with where the copy was saved and **Show in Finder**.
- **macOS 14 or later is now required.**

## Windows

- **Fixed:** the app manifest was embedded under the wrong resource type, so
  Windows ignored it. Visual styles, native task dialogs and long-path support
  now work.
- A welcome page with three large choices replaces the row of equal buttons.
- One **Unlock** dialog replaces the two-step chooser and legacy Windows
  credential prompt.
- **Open drive…** lists drives by model and size and labels the computer's own
  Windows disk; disk sizes now show without administrator rights.
- Explorer-style icons, folders listed first, a guidance bar, a description of
  the selected item, and **Show in File Explorer** after a restore.
- The window fits the screen's work area, fonts follow each monitor's DPI, Enter
  in the folder box goes there, and Ctrl+S restores.

## Attached drives

This release also includes the attached-drive work prepared after v0.8.0:

- Mac **Open a connected drive** lists external disks, including ones Finder
  can't show, suggests the partition holding the pool, and uses the standard
  macOS administrator prompt for read-only access. No privileged helper stays
  running and device permissions are not changed.
- Device size detection and sector-aligned reads for pools and standalone
  filesystems on raw and block devices.
- Fixed MBR disks whose partition at the end of the disk was misread as a
  whole-disk label.
- Windows drives open as either a pool or a standalone filesystem automatically.

## macOS installation

Requires macOS 14 or later. Open the disk image for your Mac and drag
**ZFS Explore.app** to Applications. Copy `zfs-send-extract` to a writable folder
to use the CLI from Terminal. No ZFS installation or pool mount is required.

All Mac executables use hardened runtime, a timestamped **Developer ID
Application: Austin McChord (7PTN7E8EDS)** signature, and Apple notarization.
The app and DMG have stapled tickets. The CLI tarball contains the same notarized
executable but cannot carry a ticket on the bare binary; use the DMG when
preparing for offline use.

## Validation and limitations

The real encrypted Slide Linux test backup was opened, unlocked with its key
file, its disk image opened and `/etc/hostname` restored in the Mac app and in
the Windows app — from the image file and from a read-only attached drive. Every
restored copy matches an independent OpenZFS/ext4 read. Every screen was checked
in light and dark mode on macOS and at 1280 × 800 on Windows 11. The Rust suite,
clippy with warnings denied and the Swift tests pass on Apple Silicon and
Windows, with Linux and Intel macOS in CI.

The Mac administrator prompt for attached drives needs a person to approve it and
was not exercised interactively. Windows executables remain unsigned. Sources stay
read-only; RAIDZ and pools with multiple top-level vdevs remain unsupported.
Existing v0.8.0 downloads are retained for rollback.
